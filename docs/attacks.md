# Атаки и алгоритмы агрегации в федеративном обучении

## 1. Общая идея

В федеративном обучении общая модель обучается не на одном центральном наборе данных, а на данных нескольких клиентов.

На каждом раунде выполняются следующие шаги:

1. Сервер отправляет текущую глобальную модель клиентам.
2. Каждый клиент обучает модель на своих локальных данных.
3. Клиенты отправляют серверу обновлённые параметры или градиенты.
4. Сервер объединяет клиентские обновления с помощью алгоритма агрегации.
5. Полученная модель используется в следующем раунде.

Главная проблема безопасности заключается в том, что сервер обычно не может проверить, действительно ли клиент корректно обучал модель. Вредоносный клиент может изменить данные, метки или само обновление модели.

# 2. Атаки на федеративное обучение

## Clean — эксперимент без атаки

`Clean` не является атакой. Это базовый эксперимент, в котором все клиенты обучаются честно и отправляют серверу корректные обновления.

Результаты Clean используются как эталон для сравнения с атакованными экспериментами. Если после добавления атаки точность, Precision, Recall или F1-score значительно ухудшаются, можно оценить влияние атаки на глобальную модель.

---

## Label Flipping Attack

При атаке **Label Flipping** вредоносный клиент изменяет метки объектов в своём локальном наборе данных.

Например, объект класса `1` может быть записан как класс `7`:

```text
Исходная метка: 1
Изменённая метка: 7
```

Модель получает корректное изображение, но неправильный целевой класс. В результате она обучается ошибочной зависимости между входными данными и ответами.

После локального обучения вредоносный клиент отправляет серверу обычные параметры модели. Поэтому серверу сложно определить, что обновление было получено на данных с подменёнными метками.

Основные последствия:

* снижение общей точности модели;
* ухудшение распознавания атакуемых классов;
* появление ошибок между конкретными парами классов;
* изменение значений в confusion matrix.

Label Flipping относится к атакам типа **data poisoning**, поскольку злоумышленник изменяет обучающие данные.

---

## Sign Flipping Attack

При атаке **Sign Flipping** клиент изменяет знак своего обновления модели.

Пусть честный клиент вычислил обновление:

```text
Δw
```

Вредоносный клиент отправляет:

```text
Δw_attack = -λ · Δw
```

где `λ` — коэффициент усиления атаки.

Вместо движения модели в сторону уменьшения функции потерь атакующий клиент направляет глобальную модель в противоположную сторону. При большом значении `λ` одно вредоносное обновление может существенно повлиять на результат агрегации.

Основные последствия:

* нестабильное обучение;
* резкие скачки Loss;
* снижение Accuracy и F1-score;
* возможная расходимость глобальной модели;
* сильное влияние на обычное среднее обновлений.

Sign Flipping относится к атакам типа **model poisoning**, поскольку злоумышленник изменяет не данные, а отправляемое серверу обновление модели.

## Gaussian Noise Attack

При атаке **Gaussian Noise** к параметрам или обновлению вредоносного клиента добавляется случайный гауссовский шум:

```text
Δw_attack = Δw + ε
```

где:

```text
ε ~ N(0, σ²)
```

Параметр `σ` определяет интенсивность шума. Чем больше его значение, тем сильнее повреждается клиентское обновление.

В отличие от Sign Flipping, Gaussian Noise обычно не направляет модель в строго противоположную сторону. Вместо этого атака добавляет случайные и неточные изменения.

Основные последствия:

* замедление сходимости;
* колебания метрик между раундами;
* увеличение Loss;
* снижение итоговой точности;
* нестабильность отдельных параметров модели.

Слабый шум может почти не влиять на обучение, особенно если честных клиентов много. Сильный шум способен заметно ухудшить модель или полностью нарушить процесс обучения.

Gaussian Noise относится к атакам типа **model poisoning**.

---

## Backdoor Attack

Цель **Backdoor Attack** заключается не обязательно в снижении общей точности модели. Злоумышленник пытается встроить в модель скрытое поведение.

Вредоносный клиент добавляет к части обучающих объектов специальный триггер. Например, это может быть небольшой квадрат в углу изображения. После этого таким объектам назначается выбранный атакующим целевой класс.

Пример:

```text
Изображение + триггер → целевой класс атакующего
Обычное изображение → правильный класс
```

В результате глобальная модель может правильно работать на обычных данных, но при появлении триггера выдавать заранее заданный ответ.

Для оценки Backdoor Attack необходимо использовать две группы метрик:

* качество модели на обычных тестовых данных;
* Attack Success Rate на данных с триггером.

**Attack Success Rate**, или ASR, показывает долю объектов с триггером, которые модель отнесла к целевому классу атакующего.

Опасность Backdoor Attack заключается в том, что обычная Accuracy может оставаться высокой. По стандартным метрикам модель выглядит корректной, хотя внутри неё уже присутствует скрытая уязвимость.

Backdoor относится к атакам типа **data poisoning**, хотя в некоторых реализациях она может дополнительно включать изменение обновления модели.
